# Compiler quality audit and improvements

**Request:** Find as many supported performance, quality, simplification, maintainability, and readability notes as possible and use parallel investigators to improve the branch.

**Baseline:** `4ad33d131353ff6321d13220f17621c365962178` on PR #158; comparison base `b0b7dfca564b35613319fe1855479a74c6d509d0`. The prior narrow reviews did not classify optional cleanups as findings. This audit includes those opportunities and potential hotspots, clearly separated from demonstrated defects.

**Design:** Preserve the accepted compiler architecture and observable language behavior. Remove unused state and generalized operations, share computations already available to callers, and use existing Haskell traversals when they exactly match the required order. Reproduce any correctness defect before fixing it. Keep large cache/lifetime/representation redesigns as explicit follow-ups rather than silently changing their contracts.

**Verification boundary:** No benchmark, performance, profiling, scale, or corpus-budget tests. Use focused correctness checks and compile affected consumers with the pinned Nix toolchain. Static complexity and retention observations are hypotheses, not measured performance results. Existing maintainer-deferred hosted-parser failures remain out of scope.
