# Jazz 0.1.0-alpha.1 release notes

Jazz 0.1.0-alpha.1 is the first prepared alpha of the canonical Jazz
repository. It is an experimental source and Nix release for evaluation,
language feedback, and contributor testing. These notes describe a candidate;
they do not indicate that the tag or GitHub prerelease has been published.

## Included behavior

- A statically typed, expression-oriented language with local type inference,
  explicit signatures, immutable bindings, curried functions, algebraic data
  types, pattern matching, blocks, and precedence-aware operators.
- Modules with ordered search roots, imports, explicit exports, visibility
  checks, deterministic graph loading, and cycle diagnostics.
- An interpreter-backed command-line tool for checking or running source files,
  standard input, and module entry points.
- Structured diagnostics, warning configuration, deterministic runtime
  statistics, and Speedscope-compatible runtime profiles.
- A bundled Prelude and explicit-import modules for lists, optional and result
  values, persistent collections, text and characters, and host I/O.
- Jazz-authored lexer, parser, core-lowering, typed-core validation, and
  lowered-IR validation components with differential tests against the current
  Haskell stage-0 implementation.
- Checked examples, the public language and CLI reference, compiler notes, and
  the static Docusaurus documentation site.

## Install and run

With Nix flakes enabled, build or run the canonical package from the release
source tree:

```bash
nix build .#jazz
nix run . -- --help
nix run . -- --run examples/functions/factorial.jz
```

To build from the Cabal source archive instead, use GHC 9.14.1 and a compatible
Cabal installation:

```bash
cabal build all
cabal run jazz -- --help
```

The release artifact set also includes the static documentation site. Extract
`jazz-0.1.0-alpha.1-docs.tar.gz`; `index.html` is at the archive root. The site
was built with the `/jazz/` base URL, so configure the static server to mount
the extracted directory at `/jazz/` rather than at the origin root.

The Nix artifact contains an exportable runtime closure for the system named in
its filename. On a matching system, extract and import it before running the
recorded root store path:

```bash
tar -xzf jazz-0.1.0-alpha.1-nix-<system>.tar.gz
cat nix-closure/system
nix-store --import < nix-closure/closure.nar
root_store_path="$(cat nix-closure/root-store-path)"
"$root_store_path/bin/jazz" --help
```

The closure is system-specific; it is not a portable binary bundle for a
different operating system or architecture.

## Verify downloads

Keep all four archives and `SHA256SUMS` in a directory named
`0.1.0-alpha.1`. From a checkout of the exact release source revision, run:

```bash
python3 scripts/release/verify-artifacts.py /path/to/0.1.0-alpha.1
(cd /path/to/0.1.0-alpha.1 && shasum -a 256 -c SHA256SUMS)
```

The verifier checks the exact filenames, archive safety, source version and
flake inputs, documentation publication boundary, Nix root executable,
benchmark metadata and evidence manifest, and every SHA-256 digest.

## Known limitations

- Language and standard-library compatibility is experimental and may change
  between alpha releases.
- Production compilation still uses the Haskell stage-0 compiler and
  interpreter. The tested Jazz-authored compiler components do not yet form a
  completed self-hosting pipeline.
- Typed-core production and backend-neutral lowering cover bounded opt-in
  profiles rather than every program accepted by the interpreter path.
- Capability dispatch and purity analysis remain partial.
- There is no native-code backend, production runtime, package manager, or
  language server in this alpha. The VS Code extension provides syntax
  highlighting and editor configuration only.
- This alpha is not production-stable and has no compatibility guarantee.

See `docs/project/status.md` and `docs/project/roadmap.md` for the detailed
implemented, partial, and planned boundaries.
